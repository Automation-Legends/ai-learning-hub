# Contributing to the Automation Legends AI Learning Hub

Thank you for helping make the learning hub more useful. Contributions should help members build practical skills, understand limits, and apply AI with appropriate human judgment. Small, well-tested improvements are welcome.

## Good contributions

Useful contributions include a clearer explanation, a new hands-on exercise, an improved template, a sanitized project example, a correction to an official resource link, or a lesson that helps learners evaluate an AI workflow. Every addition should be understandable without requiring a specific paid tool whenever possible.

| Contribution type | Expected standard |
|---|---|
| Lesson improvement | Explains a practical concept, includes an activity, and has a clear completion check |
| Template | Is reusable, tool-agnostic, and makes review or verification easier |
| Example project | Is sanitized, names the human-review step, and explains limitations as well as benefits |
| Resource link | Points to a credible primary source and states why it is useful |
| Correction | Identifies the affected page and provides a clear, verifiable fix |

## Before you contribute

Read the relevant learning path and confirm that your contribution fits the level of the learner. Use fictional, anonymized, or explicitly authorized material. Do not share credentials, personal data, confidential employer or client material, copyrighted content you do not have permission to publish, or instructions that bypass safety controls.

## Suggested workflow

1. Open an issue describing the learner problem you want to solve, unless the change is very small.
2. Fork the repository and create a focused branch.
3. Make the change in clear Markdown with working relative links.
4. Test all example prompts with sanitized input and explain any known limitations.
5. Add or update references for factual claims and external resources.
6. Open a pull request that explains the change, learner level, practical outcome, and any review needed.

## Content standards

Learning materials should be accurate, concise, practical, and respectful. State limitations plainly. Encourage members to verify material claims, protect sensitive information, and retain human accountability for significant decisions. Avoid implying that an AI output is automatically correct, unbiased, current, compliant, or appropriate for high-stakes use.

Use descriptive headings and tables when they help learners compare options or complete an activity. Prefer examples that demonstrate both a successful result and an exception or limitation. Keep examples tool-agnostic unless the lesson explicitly teaches a particular platform.

## Pull-request checklist

| Check | Confirm before requesting review |
|---|---|
| Scope | The contribution solves a specific learner need. |
| Clarity | The page has a clear goal, activity, and completion check. |
| Safety | Examples are sanitized and state relevant boundaries. |
| Accuracy | Important factual claims and resource links are verified. |
| Evaluation | Reusable prompts or workflows have representative test cases. |
| Accessibility | Language is clear, headings are descriptive, and tables remain readable. |
| Community fit | The contribution follows the [Code of Conduct](CODE_OF_CONDUCT.md). |

## Review process

Maintainers may request edits for clarity, accuracy, safety, or scope. They may also suggest a narrower example or additional human-review safeguard. A contribution is ready to merge when it serves the intended learner, does not expose sensitive material, and improves the hub’s practical value.
