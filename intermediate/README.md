# Intermediate Path

The Intermediate Path is for members who can already get useful AI responses and want to create **repeatable, reviewable workflows**. You will learn to define success before refining prompts, structure reusable instructions, test outputs with representative cases, and plan an automation that keeps people responsible for high-impact decisions.

> **The aim is reliability, not novelty.** A useful AI workflow has clear inputs, defined outputs, visible review points, and a way to detect when it is not working well.

## Learning sequence

| Module | What you will learn | Completion artifact |
|---|---|---|
| [1. Workflow design](01-workflow-design.md) | How to map a recurring task before adding AI | A workflow canvas with an AI opportunity and review step |
| [2. Reliable prompting](02-reliable-prompting.md) | How to structure prompts, use examples, and make outputs easier to reuse | A versioned prompt template and sample output |
| [3. Evaluation and safeguards](03-evaluation-and-safeguards.md) | How to define success criteria, test edge cases, and manage risks | A five-case evaluation sheet and escalation plan |
| [4. Build an AI automation](04-build-an-ai-automation.md) | How to specify an automation with a trigger, AI step, review, and destination | A build-ready automation specification |

## What you need

Bring one recurring task that involves text, structured notes, categorization, summarization, drafting, or decision support. You do not need to code, though you may apply the concepts with code, an API, or a no-code automation tool. Use test data or authorized, minimized data while learning.

## Principles for intermediate practice

| Principle | In practice |
|---|---|
| **Define success first** | Decide what a good output looks like before writing a more elaborate prompt. |
| **Separate instructions from data** | Keep reusable rules distinct from the material being processed. |
| **Make the output checkable** | Request a predictable structure, assumptions, and a reason for any uncertainty. |
| **Test representative cases** | Include normal, incomplete, ambiguous, and failure-prone examples. |
| **Keep human accountability** | Route consequential decisions, exceptions, and unclear results to an appropriate person. |

## You are ready to build when…

You can explain your workflow’s trigger, inputs, AI transformation, output, human review, data boundaries, fallback behavior, and success measures. If any of those fields are unclear, keep improving the workflow design before connecting tools.

## Completion standard

Complete all four modules, test your workflow with five cases, and publish a sanitized reflection using the [project showcase template](../templates/project-showcase.md). A strong showcase explains both the value created and the guardrails that make the workflow safer to use.
